Source

pub fn new() -> Self

A machine ready to run, with the entry frame already pushed.

vihaco’s locals are a window into the operand stack starting at the current frame’s base, so load/store and ret all fail with “no current frame” until one exists. A call pushes its own; @main is entered without one, so the machine establishes it.

Source

pub fn with_arch(self, arch: ArchSpec) -> Self

Point the machine at an architecture. move cannot resolve a lane into (src, dst) endpoints without one, so it fails until this is set.

Source

pub fn run(&mut self, program: &Program, max_steps: u64) -> Result<Run>

Run a program: dispatch each instruction to the device that owns it, until it halts, returns, or runs out of code or budget.

This is the piece that makes the composite a machine rather than two devices: step_lanes handles one lanes instruction, CPU::execute_instruction one CPU instruction, and nothing until now walked a MachineInstruction stream across both.

max_steps bounds execution. A program with a backward branch can run forever, and the ISA carries vihaco-cpu’s control flow whether or not the lanes compiler emits it, so the budget is a parameter rather than an assumption.

Source

pub fn step_lanes( &mut self, inst: LanesInstruction, ) -> Result<Effects<LanesEffect>>

Run one lanes instruction end to end: pop its operands, execute, then apply whatever comes back.
