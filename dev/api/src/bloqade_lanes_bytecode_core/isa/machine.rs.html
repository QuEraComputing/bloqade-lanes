1//! The Bloqade Lanes machine: vihaco-cpu's `CPU` plus our atom-movement device.
2//!
3//! This is the idiomatic vihaco composition, and the same shape PPVM uses: each
4//! device owns its instruction set, and `#[composite]` generates the combined
5//! program type, the text parser (an alternation over the devices' parsers) and
6//! the section loaders.
7//!
8//! ```text
9//! cpu::cpu.const u64, 0      <- vihaco-cpu's device
10//! lanes::lanes.move 2        <- ours
11//! ```
12//!
13//! The `<field>::` prefix is the device field name; the second half is that
14//! device's own dialect head.
15//!
16//! ## Who does what
17//!
18//! Instruction operands live on the CPU stack, so a device never reads them
19//! directly. `resolve_lanes` pops them and packs them into a [`LanesMessage`];
20//! the device executes; the machine then applies any [`LanesEffect::Push`]
21//! back onto the stack. That round trip is the reason address constants can
22//! stay lanes instructions while still behaving like stack pushes.
23//!
24//! [`super::validate::simulate_stack`] is the static half of this: it models
25//! the same pops *and the same pushes*, so a program it accepts does not
26//! underflow on any path it checks. That is every path except those past a
27//! `call_indirect`, whose arity only the run knows, and any path merging with
28//! one (TODO(vihaco#110): close with a declared signature on `call_indirect`).
29//! The ops the device does not interpret hold up their end by pushing
30//! [`Value::Undefined`] placeholders — the depth the simulator predicts, with
31//! a value nothing can mistake for a result.
32//!
33//! ## Frames: vihaco#110's model, emulated on 0.4.1
34//!
35//! vihaco 0.4.1 gives a function no locals of its own: `call arity` sets
36//! `base = stack.len() - arity`, and local `n` is `stack[base + n]`, so past
37//! the arguments a local *is* whatever was pushed next. vihaco#110 (merged
38//! upstream, in no release yet) splits the frame instead:
39//!
40//! ```text
41//! [caller's values][locals: parameters, then scratch][operands]
42//!                   ^ base                            ^ base + local_count
43//! ```
44//!
45//! This machine runs that model today, so the compiler and the validator can
46//! be written against it once. On entry and after every `call` it reserves
47//! the callee's [`local_count`](vihaco::module::FunctionInfo::local_count)
48//! slots past its arguments; every operand pop, CPU or lanes, is floored at
49//! the first operand; and `load`/`store` must name a reserved slot, so a
50//! `store` can no longer grow the stack.
51//!
52//! A reserved slot starts as [`Value::Undefined`], and a typed `load` of any
53//! local holding `Undefined` reads that type's zero — whether nothing wrote
54//! it or it holds a placeholder a lanes op pushed, stored or passed in as an
55//! argument. That is what the bump will do: #110 zero-fills the frame, and
56//! under vihaco#85's untyped words a placeholder is a zero word too, and no
57//! `load` can fail on a type. A local holding a *concrete* value of another
58//! type is still 0.4.1's type error; `load undef` reads a placeholder as
59//! itself and refuses every concrete value.
60//!
61//! TODO(vihaco#110): the bump deletes this shim — `frame_locals`,
62//! [`push_locals`](LanesMachine::push_locals), the operand floor and the
63//! zero-reading `load` — and passes `local_count` to the CPU in its
64//! `FunctionInfo` message instead. [`check_frame`](LanesMachine::check_frame)
65//! stays, in front of that message. Nothing outside this module changes.

82/// Most values the stack may hold after any instruction.
83///
84/// A frame reserves at most [`MAX_LOCAL_COUNT`] locals, but recursion reserves
85/// a frame per level, and a loop that only pushes grows the stack without
86/// reserving anything. The step budget bounds both only as loosely as the
87/// caller chose it, so the stack has a bound of its own: 2²⁰ values is 16 MB,
88/// room for a thousand levels of the largest frame or a million of the
89/// smallest.
90///
91/// Checked once per step, in [`run_with_args`](LanesMachine::run_with_args).
92/// That covers every way the stack grows — CPU pushes, lanes effects, and
93/// reserved locals — because no instruction grows it by more than one value
94/// except a `call`, which reserves at most [`MAX_LOCAL_COUNT`]; so the stack
95/// never overshoots the bound by more than one frame.
96///
97/// TODO(vihaco#110): the bump keeps this. #110's `call` still resizes the
98/// stack to reserve the callee's locals.
99pub const MAX_STACK_SLOTS: usize = 1 << 20;

107/// `#[composite]` derives only `Debug` and `Clone` on its runtime enum, but both
108/// device instruction sets *are* `PartialEq`, so comparing programs only needs
109/// the two arms spelled out. Round-trip tests and the Python `__eq__` both rely
110/// on it.
111impl PartialEq for MachineInstruction {
112    fn eq(&self, other: &Self) -> bool {
113        match (self, other) {
114            (Self::Cpu(a), Self::Cpu(b)) => a == b,
115            (Self::Lanes(a), Self::Lanes(b)) => a == b,
116            _ => false,
117        }
118    }
119}

209    /// Run a program: dispatch each instruction to the device that owns it,
210    /// until it halts, returns, or runs out of code or budget.
211    ///
212    /// This is the piece that makes the composite a machine rather than two
213    /// devices: [`step_lanes`](Self::step_lanes) handles one lanes
214    /// instruction, `CPU::execute_instruction` one CPU instruction, and
215    /// nothing until now walked a `MachineInstruction` stream across both.
216    ///
217    /// `max_steps` bounds execution. A program with a backward branch can run
218    /// forever, and the ISA carries vihaco-cpu's control flow whether or not
219    /// the lanes compiler emits it, so the budget is a parameter rather than
220    /// an assumption.
221    ///
222    /// The entry point is entered with no arguments; one that declares
223    /// parameters needs [`run_with_args`](Self::run_with_args).
224    pub fn run(&mut self, program: &Program, max_steps: u64) -> eyre::Result<Run> {
225        self.run_with_args(program, &[], max_steps)
226    }

228    /// [`run`](Self::run) an entry point that takes arguments.
229    ///
230    /// `args` are pushed before the first instruction, in declaration order,
231    /// so they sit at the bottom of the entry frame as locals `0..args.len()`
232    /// — where a `call` leaves a callee's. That is the frame `simulate_stack`
233    /// assumes for every function, the entry included.
234    ///
235    /// They are checked against the entry point's declaration, count and
236    /// type, the way `validate` checks a `call` against its callee's. The host
237    /// is the entry point's only caller, and without the check a missing
238    /// argument surfaces mid-run as an out-of-bounds `load`, far from its
239    /// cause.
240    pub fn run_with_args(
241        &mut self,
242        program: &Program,
243        args: &[Value],
244        max_steps: u64,
245    ) -> eyre::Result<Run> {
246        use vihaco_cpu::StepOutcome;
247
248        let mut effects = Vec::new();
249        let mut steps = 0u64;
250        let mut pc = self.enter(program, args)?;
251
252        let stopped = loop {
253            let Some(inst) = program.code.get(pc) else {
254                break Stopped::RanOff;
255            };
256            if steps == max_steps {
257                break Stopped::OutOfSteps;
258            }
259            steps += 1;
260
261            // `op_call` reads this to work out where to return to, so it has
262            // to be set before the instruction runs, not after.
263            self.cpu.set_current_pc(pc as u32);
264
265            match inst {
266                MachineInstruction::Lanes(inst) => {
267                    collect(self.step_lanes(inst.clone())?, &mut effects);
268                }
269                MachineInstruction::Cpu(inst) => {
270                    match self.step_cpu(program, inst)? {
271                        StepOutcome::Halt => break Stopped::Halted,
272                        // `op_return` reports `Return` only when it pops the
273                        // last frame; an inner return sets the resume address
274                        // and reports `Continue`.
275                        StepOutcome::Return => break Stopped::Returned,
276                        StepOutcome::Continue | StepOutcome::Breakpoint => {}
277                    }
278                }
279            }
280
281            let depth = self.cpu.stack().len();
282            if depth > MAX_STACK_SLOTS {
283                eyre::bail!(
284                    "the stack holds {depth} values, past the maximum of {MAX_STACK_SLOTS}: \
285                     unbounded recursion, or a loop that only pushes?"
286                );
287            }
288
289            // A branch or call leaves its destination here; anything else
290            // falls through to the next instruction.
291            pc = match self.cpu.take_pending_pc() {
292                Some(target) => target as usize,
293                None => pc + 1,
294            };
295        };
296
297        Ok(Run {
298            effects,
299            stopped,
300            steps,
301        })
302    }

304    /// Run one CPU instruction inside vihaco#110's frame model.
305    ///
306    /// vihaco-cpu 0.4.1 executes it; this supplies what 0.4.1 lacks around
307    /// it (see the module docs). Checks come first and are made against the
308    /// operands alone, for the same reason
309    /// [`pop_capacity`](Self::pop_capacity) clamps its reservation: `run` has
310    /// no validation gate — `validate` is its own subcommand, and a program
311    /// you have not validated is still one you may want to execute.
312    ///
313    /// Two upstream hazards cannot be reached from here, and no longer need
314    /// guards of their own:
315    ///
316    /// - `store` ([#1032]): `op_store` `resize`s the stack to reach an index
317    ///   past its top — 68 GB for `store u64, 4294967295`. Every index must
318    ///   now be a reserved slot, all of which exist below the operands.
319    /// - `ret` ([#1033]): `op_return` subtracts `frame.base` from the depth
320    ///   assuming the callee never popped below it, and a panic followed when
321    ///   one did. No pop reaches past the locals now, let alone the base.
322    ///
323    /// [#1032]: https://github.com/QuEraComputing/bloqade-lanes/issues/1032
324    /// [#1033]: https://github.com/QuEraComputing/bloqade-lanes/issues/1033
325    fn step_cpu(
326        &mut self,
327        program: &Program,
328        inst: &vihaco_cpu::RuntimeInstruction,
329    ) -> eyre::Result<vihaco_cpu::StepOutcome> {
330        use vihaco_cpu::RuntimeInstruction as C;
331        use vihaco_cpu::StepOutcome;
332
333        if let C::Load(_, index) | C::Store(_, index) = inst {
334            let reserved = self.current_locals();
335            if *index >= reserved {
336                eyre::bail!(
337                    "{} names local {index}, but the frame reserves {reserved}",
338                    cpu_op_name(inst)
339                );
340            }
341        }
342        let needed = cpu_operands(inst, self.cpu.stack());
343        let have = self.operand_count();
344        if have < needed {
345            eyre::bail!(
346                "stack underflow: {} takes {needed} operand(s), and the frame has \
347                 {have} above its locals",
348                cpu_op_name(inst)
349            );
350        }
351
352        // A local holding `Undefined` — unwritten, or a stored or passed
353        // placeholder — reads as the zero of the type that loads it, as the
354        // bump's untyped, zero-filled frames will (see the module docs).
355        // 0.4.1 would fail the `load` instead: an `Undefined` is not the type
356        // it names. `load undef` still reads the placeholder itself.
357        if let C::Load(ty, index) = inst
358            && *ty != Type::Undefined
359            && self.local(*index) == Some(&Value::Undefined)
360        {
361            self.cpu.stack_push(zero_of(*ty));
362            return Ok(StepOutcome::Continue);
363        }
364
365        // Resolve the callee, and refuse its frame, before the CPU pushes one:
366        // a refusal then leaves `frame_locals` and the CPU's frames in step.
367        // That is #110's order too — its `call` checks the `local_count` in
368        // its `FunctionInfo` message before entering. And it is #110's check:
369        // `arity <= local_count`, not that the arity equals the declared
370        // parameter count. `validate`'s `CallArityMismatch` covers a direct
371        // call, and after the bump `call_indirect` takes its arity from the
372        // function table rather than the stack.
373        let frame = match inst {
374            C::Call(arity, target) => Some(self.plan_frame(program, *target, *arity as usize)?),
375            // The target is on top and the arity below it. Anything else is
376            // not a call at all, and `op_indirect_call` says so.
377            C::IndirectCall => {
378                let stack = self.cpu.stack();
379                match (stack.last(), stack.len().checked_sub(2).map(|i| &stack[i])) {
380                    (Some(Value::U32(target)), Some(Value::U32(arity))) => {
381                        Some(self.plan_frame(program, *target, *arity as usize)?)
382                    }
383                    _ => None,
384                }
385            }
386            _ => None,
387        };
388
389        let outcome = self.cpu.execute_instruction(inst.clone())?;
390        if let Some(local_count) = frame {
391            // `op_call` just set `base = stack.len() - arity`, so the
392            // arguments are already the first locals.
393            let arity = self.cpu.stack().len() - self.cpu.get_frame()?.base;
394            self.push_locals(local_count, arity);
395        } else if matches!(inst, C::Return(_)) {
396            // Reached only when `op_return` succeeded, and so popped a frame.
397            self.frame_locals.pop();
398        }
399        Ok(outcome)
400    }

402    /// The locals a call to `target` with `arity` arguments reserves, once
403    /// [`check_frame`](Self::check_frame) has passed them.
404    fn plan_frame(&self, program: &Program, target: u32, arity: usize) -> eyre::Result<u32> {
405        let function = program
406            .functions
407            .iter()
408            .find(|f| f.start_address == target)
409            .ok_or_else(|| eyre::eyre!("call target {target} does not begin a function"))?;
410        self.check_frame(function.local_count, arity)?;
411        Ok(function.local_count)
412    }

414    /// Refuse a frame of `local_count` locals, the first `arity` of them
415    /// arguments already on the stack, before anything is reserved:
416    ///
417    /// - below its arity, as #110's `call` does;
418    /// - past [`MAX_LOCAL_COUNT`]. The count is the table's, and a program
419    ///   that was never validated could otherwise ask every call to reserve
420    ///   four billion slots, which is #1032 again by another road.
421    ///
422    /// How many frames recursion stacks up is [`MAX_STACK_SLOTS`]'s job,
423    /// checked once per step with every other way the stack grows.
424    fn check_frame(&self, local_count: u32, arity: usize) -> eyre::Result<()> {
425        if local_count > MAX_LOCAL_COUNT {
426            eyre::bail!(
427                "the frame reserves {local_count} locals, past the maximum of {MAX_LOCAL_COUNT}"
428            );
429        }
430        if (local_count as usize) < arity {
431            eyre::bail!(
432                "the frame receives {arity} argument(s) but reserves only {local_count} \
433                 local(s), which must include them"
434            );
435        }
436        Ok(())
437    }

439    /// Reserve a new frame's locals past its `arity` arguments, which are
440    /// already in place as locals `0..arity`. Checked beforehand by
441    /// [`check_frame`](Self::check_frame).
442    fn push_locals(&mut self, local_count: u32, arity: usize) {
443        let extra = (local_count as usize).saturating_sub(arity);
444        self.cpu
445            .stack_mut()
446            .extend(std::iter::repeat_n(Value::Undefined, extra));
447        self.frame_locals.push(local_count);
448    }

471    /// Pop one operand, refusing to reach into the frame's locals.
472    fn pop_operand(&mut self) -> eyre::Result<Value> {
473        if self.operand_count() == 0 {
474            eyre::bail!("stack underflow: the frame has no operands above its locals");

479    /// Where execution begins: the `@main` *symbol*, not byte zero.
480    ///
481    /// A lanes program is an executable, so it enters the way a linked binary
482    /// does — at a named entry the loader resolves, wherever it was laid out.
483    /// Starting at address 0 instead ran whichever function came first in the
484    /// source, so a module declaring `@helper` before `@main` executed the
485    /// wrong one and reported success.
486    ///
487    /// Pushes the entry point's arguments, checked against its declared
488    /// parameters, reserves the rest of its locals, and returns the address
489    /// to start at.
490    ///
491    /// Every run starts from a reset CPU holding only the entry frame, so the
492    /// arguments land at locals `0..n` however the machine was last left: a
493    /// halt mid-callee leaves frames and operands behind, and a `ret` from
494    /// `@main` pops the entry frame outright.
495    fn enter(&mut self, program: &Program, args: &[Value]) -> eyre::Result<usize> {
496        let function = super::program::entry_function(program)?;
497
498        let params = &function.signature.params;
499        if args.len() != params.len() {
500            eyre::bail!(
501                "the entry point declares {} parameter(s), but {} argument(s) were supplied",
502                params.len(),
503                args.len()
504            );
505        }
506        for (i, (arg, param)) in args.iter().zip(params).enumerate() {
507            if arg.type_of() != param.ty {
508                eyre::bail!(
509                    "entry argument {i} is {:?}, but the entry point declares {:?}",
510                    arg.type_of(),
511                    param.ty
512                );
513            }
514        }
515        vihaco::Reset::reset(&mut self.cpu);
516        self.frame_locals.clear();
517        self.cpu.push_frame(entry_frame());
518        for arg in args {
519            self.cpu.stack_push(*arg);
520        }
521        self.check_frame(function.local_count, args.len())?;
522        self.push_locals(function.local_count, args.len());
523
524        Ok(function.start_address as usize)
525    }

527    /// Pop the operands `inst` consumes and pack them into its message.
528    ///
529    /// Pops are in reverse push order throughout: the last value pushed is the
530    /// first popped, so a group read back from the stack is reversed to restore
531    /// program order.
532    fn resolve_lanes(&mut self, inst: &LanesInstruction) -> eyre::Result<LanesMessage> {
533        use LanesInstruction as I;
534        Ok(match inst {
535            // Constants carry their operand in the instruction word.
536            I::ConstLoc(_) | I::ConstLane(_) | I::ConstZone(_) => LanesMessage::None,
537
538            I::InitialFill(n) | I::Fill(n) => LanesMessage::Locations(self.pop_locations(*n)?),
539            I::Move(n) => LanesMessage::Lanes(self.pop_lanes(*n)?),
540
541            // Angles sit above the locations: `local_r` pops axis then
542            // rotation, then the location group beneath them.
543            I::LocalR(n) => LanesMessage::LocalRotation {
544                angles: self.pop_floats(2)?,
545                locations: self.pop_locations(*n)?,
546            },
547            I::LocalRz(n) => LanesMessage::LocalRotation {
548                angles: self.pop_floats(1)?,
549                locations: self.pop_locations(*n)?,
550            },
551            I::GlobalR => LanesMessage::GlobalRotation {
552                angles: self.pop_floats(2)?,
553            },
554            I::GlobalRz => LanesMessage::GlobalRotation {
555                angles: self.pop_floats(1)?,
556            },
557
558            I::Cz => LanesMessage::Zones(self.pop_zones(1)?),
559            I::Measure(n) => LanesMessage::Zones(self.pop_zones(*n)?),
560
561            // `new_array` consumes dim0×dim1 elements (dim1 = 0 means 1-D);
562            // `get_item` consumes the array reference and then its indices.
563            // Both are reported rather than executed — see
564            // [`LanesEffect::NotSimulated`] — so the operands travel with the
565            // message rather than being dropped on the floor.
566            //
567            // Both counts are computed in `u64`: `dim0 * dim1` overflows `u32`
568            // for operands a decoded program is free to carry, and `n + 1`
569            // overflows for `get_item(u32::MAX)`.
570            I::NewArray(_, dim0, dim1) => {
571                LanesMessage::Values(self.pop_values(array_element_count(*dim0, *dim1))?)
572            }
573            I::GetItem(n) => LanesMessage::Values(self.pop_values(*n as u64 + 1)?),
574
575            I::AwaitMeasure | I::SetDetector | I::SetObservable => {
576                LanesMessage::Values(self.pop_values(1)?)
577            }
578        })
579    }

581    /// Pop `n` values, restoring program order (the last pushed is popped
582    /// first).
583    ///
584    /// `n` comes straight out of an instruction word, so nothing is
585    /// pre-allocated against it: an implausible count runs out of stack within
586    /// a few pops and fails there. [`super::validate::validate_structure`]
587    /// rejects such a program up front; this makes the machine safe on its own
588    /// regardless.
589    fn pop_values(&mut self, n: u64) -> eyre::Result<Vec<Value>> {
590        let mut out = Vec::with_capacity(self.pop_capacity(n));
591        for _ in 0..n {
592            out.push(self.pop_operand()?);
593        }
594        out.reverse();
595        Ok(out)
596    }
597
598    /// Capacity to reserve for a pop of `n` values.
599    ///
600    /// `n` comes straight out of an instruction word, so it cannot be used as
601    /// a capacity: `initial_fill 4294967295` asks for 48 GiB of
602    /// `LocationAddr`. Linux's allocator refuses and Rust aborts the process
603    /// (SIGABRT, no unwinding, no test failure to catch); macOS commits
604    /// lazily and hands it back, which is why this only ever showed up in CI.
605    ///
606    /// A pop can never take more than the frame's operands, so their count is
607    /// both a safe bound and a sufficient one — every legitimate arity still
608    /// gets its single up-front allocation.
609    fn pop_capacity(&self, n: u64) -> usize {
610        n.min(self.operand_count() as u64) as usize
611    }

613    fn pop_u64(&mut self) -> eyre::Result<u64> {
614        match self.pop_operand()? {
615            Value::U64(v) => Ok(v),
616            v => Err(eyre::eyre!("expected a packed u64 address, got {v:?}")),
617        }
618    }

620    fn pop_floats(&mut self, n: u32) -> eyre::Result<Vec<f64>> {
621        let mut out = Vec::with_capacity(self.pop_capacity(n as u64));
622        for _ in 0..n {
623            match self.pop_operand()? {
624                Value::F64(v) => out.push(v),
625                v => return Err(eyre::eyre!("expected an angle (f64), got {v:?}")),
626            }
627        }
628        out.reverse();
629        Ok(out)
630    }

635            out.push(LocationAddr::decode(self.pop_u64()?));

641    fn pop_lanes(&mut self, n: u32) -> eyre::Result<Vec<LaneAddr>> {

643        for _ in 0..n {
644            out.push(LaneAddr::decode_u64(self.pop_u64()?));

650    fn pop_zones(&mut self, n: u32) -> eyre::Result<Vec<ZoneAddr>> {

656            }
657        }
658        out.reverse();
659        Ok(out)
660    }

662    /// Apply a device effect. Only [`LanesEffect::Push`] touches the machine;
663    /// the rest are observations for the caller.
664    fn apply(&mut self, effects: &Effects<LanesEffect>) -> eyre::Result<()> {
665        let mut push = |effect: &LanesEffect| {
666            if let LanesEffect::Push(value) = effect {
667                self.cpu.stack_push(*value);
668            }
669        };
670        match effects {
671            Effects::None => {}
672            Effects::One(effect) => push(effect),
673            Effects::Many(effects) => effects.iter().for_each(push),
674        }
675        Ok(())
676    }

693/// How many operands a CPU instruction consumes, so they can be floored at
694/// the frame's locals before vihaco-cpu 0.4.1 — which floors nothing — pops
695/// them. `dup` only reads its operand, but it still needs one.
696///
697/// Exhaustive on purpose: an instruction a vihaco bump adds has to be counted
698/// here before it compiles, rather than defaulting to zero and popping into
699/// the locals unchecked.
700///
701/// TODO(vihaco#110): upstream floors every operand pop itself.
702fn cpu_operands(inst: &vihaco_cpu::RuntimeInstruction, stack: &[Value]) -> usize {
703    use vihaco_cpu::RuntimeInstruction as C;
704    match inst {
705        C::Const(..)
706        | C::Load(..)
707        | C::Branch(_)
708        | C::Halt
709        | C::Label(_)
710        | C::Span(..)
711        | C::Breakpoint
712        | C::FunctionStart
713        | C::FunctionEnd => 0,
714        C::Dup
715        | C::Store(..)
716        | C::ConditionalBranch(..)
717        | C::Print
718        | C::HeapDealloc
719        | C::Neg(_)
720        | C::Not => 1,
721        C::GetItem
722        | C::Add(_)
723        | C::Sub(_)
724        | C::Mul(_)
725        | C::Div(_)
726        | C::Rem(_)
727        | C::Shl(_)
728        | C::Shr(_)
729        | C::Rol(_)
730        | C::Ror(_)
731        | C::BitAnd(_)
732        | C::BitOr(_)
733        | C::BitXor(_)
734        | C::And
735        | C::Or
736        | C::Xor
737        | C::Eq(_)
738        | C::Ne(_)
739        | C::Lt(_)
740        | C::Gt(_)
741        | C::Le(_)
742        | C::Ge(_) => 2,
743        C::HeapAlloc(n) => *n as usize,
744        C::Return(keep) => *keep as usize,
745        C::Call(arity, _) => *arity as usize,
746        // Function reference, arity and target, then the arguments beneath
747        // them. The arity is itself an operand, second from the top; one that
748        // is not a `u32` fails in `op_indirect_call` before any argument is
749        // taken.
750        C::IndirectCall => {
751            let arity = match stack.len().checked_sub(2).map(|i| &stack[i]) {
752                Some(Value::U32(arity)) => *arity as usize,
753                _ => 0,
754            };
755            3 + arity
756        }
757    }
758}

1029/// Lower a parsed vihaco-cpu instruction to its runtime form.
1030///
1031/// The surface form is lexical — `SurfaceValue` is a raw token and branch
1032/// targets are identifiers — so this is where a constant becomes a typed
1033/// [`Value`].
1034///
1035/// What this accepts is the counterpart of what [`to_sst_text`] emits: a
1036/// decoded binary may hold any of vihaco's nine `const` types, so all nine
1037/// parse back. The two rejections both need something a per-instruction
1038/// lowering does not have — a symbol table, for symbolic control flow, and a
1039/// string table, for a quoted literal.
1040fn lower_cpu(inst: CpuSurfaceInstruction) -> eyre::Result<vihaco_cpu::RuntimeInstruction> {
1041    use CpuSurfaceInstruction as S;
1042    use vihaco_cpu::RuntimeInstruction as R;
1043
1044    let ty = |t: vihaco_cpu::SurfaceType| -> Type {
1045        match t {
1046            vihaco_cpu::SurfaceType::Undefined => Type::Undefined,
1047            vihaco_cpu::SurfaceType::String => Type::String,
1048            vihaco_cpu::SurfaceType::Bool => Type::Bool,
1049            vihaco_cpu::SurfaceType::I64 => Type::I64,
1050            vihaco_cpu::SurfaceType::U32 => Type::U32,
1051            vihaco_cpu::SurfaceType::U64 => Type::U64,
1052            vihaco_cpu::SurfaceType::F64 => Type::F64,
1053            vihaco_cpu::SurfaceType::FunctionRef => Type::FunctionRef,
1054            vihaco_cpu::SurfaceType::HeapRef => Type::HeapRef,
1055        }
1056    };
1057
1058    Ok(match inst {
1059        S::Const(t, v) => {
1060            let ty = ty(t);
1061            // A quoted literal would have to be interned to become a
1062            // `Value::String`, and interning needs the module's string table —
1063            // which a per-instruction lowering does not have. `const str` takes
1064            // the interner index instead, which is what the value holds and
1065            // what `cpu_value_text` renders.
1066            let text = match &v {
1067                vihaco_cpu::SurfaceValue::Bare(token) => token.0.clone(),
1068                vihaco_cpu::SurfaceValue::Quoted(_) => {
1069                    return Err(eyre::eyre!(
1070                        "a quoted string literal needs the module's string table; \
1071                         write the interner index instead"
1072                    ));
1073                }
1074            };
1075            // Every type the renderer can emit must parse back, or
1076            // `disassemble` produces text `assemble` rejects. The three
1077            // reference types and `String` are interner/heap indices, so they
1078            // read as plain integers.
1079            let value = match ty {
1080                Type::F64 => Value::F64(text.parse()?),
1081                Type::I64 => Value::I64(text.parse()?),
1082                Type::U64 => Value::U64(text.parse()?),
1083                Type::U32 => Value::U32(text.parse()?),
1084                Type::Bool => Value::Bool(text.parse()?),
1085                Type::String => Value::String(text.parse()?),
1086                Type::FunctionRef => Value::FunctionRef(text.parse()?),
1087                Type::HeapRef => Value::HeapRef(text.parse()?),
1088                Type::Undefined if text == "undef" => Value::Undefined,
1089                Type::Undefined => {
1090                    return Err(eyre::eyre!("const undef takes no value but got '{text}'"));
1091                }
1092            };
1093            R::Const(ty, value)
1094        }
1095        S::Span(a, b, c) => R::Span(a, b, c),
1096        S::FunctionStart => R::FunctionStart,
1097        S::FunctionEnd => R::FunctionEnd,
1098        S::Breakpoint => R::Breakpoint,
1099        S::Return(n) => R::Return(n),
1100        S::IndirectCall => R::IndirectCall,
1101        S::Halt => R::Halt,
1102        S::Print => R::Print,
1103        S::Load(t, addr) => R::Load(ty(t), addr),
1104        S::Store(t, addr) => R::Store(ty(t), addr),
1105        S::Dup => R::Dup,
1106        S::HeapAlloc(n) => R::HeapAlloc(n),
1107        S::GetItem => R::GetItem,
1108        S::HeapDealloc => R::HeapDealloc,
1109        S::Add(t) => R::Add(ty(t)),
1110        S::Sub(t) => R::Sub(ty(t)),
1111        S::Mul(t) => R::Mul(ty(t)),
1112        S::Div(t) => R::Div(ty(t)),
1113        S::Rem(t) => R::Rem(ty(t)),
1114        S::Neg(t) => R::Neg(ty(t)),
1115        S::Shl(t) => R::Shl(ty(t)),
1116        S::Shr(t) => R::Shr(ty(t)),
1117        S::Rol(t) => R::Rol(ty(t)),

2331    /// A full text spelling is `<device>::<dialect>.<mnemonic>`. The narrower
2332    /// `cpu::add` form also appears in the docs — it is how a `DecodingError`
2333    /// names an instruction — but that is `op_name`, not a text mnemonic.
2334    fn is_text_spelling(token: &str) -> bool {
2335        token
2336            .split_once("::")
2337            .and_then(|(device, rest)| {
2338                let (dialect, mnemonic) = rest.split_once('.')?;
2339                Some(
2340                    matches!(device, "cpu" | "lanes")
2341                        && matches!(dialect, "cpu" | "lanes")
2342                        && !mnemonic.is_empty(),
2343                )
2344            })
2345            .unwrap_or(false)
2346    }

2348    /// The first text spelling in `line`, if any.
2349    fn mnemonic_in(line: &str) -> Option<&str> {
2350        line.split(|c: char| !(c.is_alphanumeric() || c == '_' || c == ':' || c == '.'))
2351            .map(|t| t.trim_end_matches('.'))
2352            .find(|t| is_text_spelling(t))
2353    }

2391    /// Every `Opcode` the docs tabulate must be the one the encoder produces.
2392    ///
2393    /// The spec prints a literal for each instruction, and nothing pinned
2394    /// them: they are assigned by declaration order, so they renumber whenever
2395    /// either instruction set gains a variant. The guide tells readers to
2396    /// compare on `op_name()` for exactly that reason — but a *format spec*
2397    /// that omits the byte values is not much of a format spec, so they stay
2398    /// and are checked here instead.
2399    #[test]
2400    fn every_documented_opcode_matches_the_encoding() {
2401        let real = real_mnemonics();
2402        let mut wrong = Vec::new();
2403        let mut checked = 0;
2404
2405        for (file, text) in DOCS {
2406            // `inst-spec.md` puts the mnemonic in a `#### ` heading and the
2407            // value in an `| Opcode | 0x.. |` row; `inst-quick-ref.md` puts
2408            // both in one row. Track the heading so either shape resolves.
2409            let mut heading: Option<&str> = None;
2410            for line in text.lines() {
2411                if let Some(rest) = line.strip_prefix("#### ") {
2412                    heading = mnemonic_in(rest);
2413                    continue;
2414                }
2415                if !line.starts_with('|') {
2416                    continue;
2417                }
2418                let Some(documented) = hex_in(line) else {
2419                    continue;
2420                };
2421                // Either the row names the instruction itself, or it is the
2422                // `Opcode` row belonging to the heading above it. Anything
2423                // else carrying a hex literal (the device-code table) is not
2424                // an opcode claim.
2425                let first_cell = line.split('|').nth(1).map(str::trim).unwrap_or("");
2426                let Some(name) = mnemonic_in(line).or(if first_cell == "Opcode" {
2427                    heading
2428                } else {
2429                    None
2430                }) else {
2431                    continue;
2432                };
2433
2434                match real.get(name) {
2435                    Some(actual) if *actual == documented => checked += 1,
2436                    Some(actual) => wrong.push(format!(
2437                        "  {file}: `{name}` documented as {documented:#06x}, encodes as {actual:#06x}"
2438                    )),
2439                    // The mnemonic test covers unknown names.
2440                    None => {}
2441                }
2442            }
2443        }
2444
2445        assert!(
2446            wrong.is_empty(),
2447            "{} documented opcode(s) disagree with the encoding:\n{}",
2448            wrong.len(),
2449            wrong.join("\n")
2450        );
2451        // A parser that silently matched nothing would make this vacuous:
2452        // 29 rows in the quick reference plus 23 in the spec.
2453        assert_eq!(
2454            checked, 52,
2455            "expected 52 documented opcodes, found {checked}"
2456        );
2457    }
